# SX1262 GFSK presets at 868 MHz

This branch (`sx1262-fsk`) builds on `sx1280-fast-modems` and runs its four GFSK presets on SX126x radios in region
`EU_868`. Same preset numbers, same frame (4-byte sync word `2D 4B D4 93`, 2-byte CRC, variable length); the physical
parameters depend on the band. FLRC stays 2.4 GHz only.

## Presets (sub-GHz)

All four plan one 250 kHz channel, as LONG_FAST does, so in EU_868 they sit at 869.525 MHz inside 869.4-869.65 MHz.
The receiver filter is the smallest SX126x step that holds Carson's bandwidth (bit rate + 2 × deviation).

| Preset | No. | Bit rate | Deviation | RX filter | Occupied (Carson) | Sensitivity (est.) |
|---|---|---|---|---|---|---|
| GFSK_TURBO | 72 | 150 kb/s | 37.5 kHz (h = 0.5) | 234.3 kHz | 225 kHz | −105 dBm |
| GFSK_FAST | 73 | 100 kb/s | 50 kHz (h = 1) | 234.3 kHz | 200 kHz | −106 dBm |
| GFSK_MEDIUM | 74 | 50 kb/s | 25 kHz | 117.3 kHz | 100 kHz | −108 dBm |
| GFSK_LONG | 75 | 25 kb/s | 12.5 kHz | 58.6 kHz | 50 kHz | −111 dBm |

Sensitivities are interpolated from the SX1262 datasheet's FSK rows (−118 dBm at 4.8 kb/s, −109 at 38.4, −104 at 250).

```bash
meshtastic --port COM38 --set lora.region EU_868
meshtastic --port COM38 --set lora.modem_preset 72
```

They are in `EU_868`'s own preset list only (not advertised to clients, which do not know them). On a radio that cannot
run GFSK, or in another region, the node falls back to the region default.

## Driver

- `SX126xInterface::programGfsk()` runs `SX126x::beginFSK()` (qualified: the SX1262 overload would read the bit rate
  as the frequency) and then everything a reset chip loses: frequency, sync word, CRC, packet length mode, current
  limit, DIO2 RF switch, TCXO standby, RF switch pins, the 0x8B5 RX patch, power and RX gain. Going back to LoRa takes
  `reinitChip()`.
- RX stays continuous, with SYNC_WORD_VALID enabled; `isActivelyReceiving()` counts only a valid sync word, so a
  noise-tripped preamble detector cannot start the LoRa-sized preamble hold.
- Carrier sense: no CAD; busy while a sync word is being received or RSSI is 10 dB over the larger of the preset's
  sensitivity and the noise floor.
- Airtime, RSSI-derived SNR and timing (1 ms slot, 1000 ms retransmission base, 10 ms TX gap) as on the SX1280.

## Results

Two ProMicro nRF52840 + Ebyte E22P (SX1262) boards in one room at −9 dBm chip output (RSSI −6 dBm), region EU_868,
20 messages of 200 bytes, measured end to end through the serial API, firmware built from `nrf52_promicro_diy_tcxo`.

| Preset | ACK delivered | Median ACK latency | Stream received | Stream rate |
|---|---|---|---|---|
| GFSK_TURBO (150 kb/s) | 20/20 | 83 ms | 20/20 | 29.4 kb/s |
| GFSK_FAST (100 kb/s) | 20/20 | 89 ms | 20/20 | 29.2 kb/s |
| GFSK_MEDIUM (50 kb/s) | 20/20 | 114 ms | 20/20 | 23.6 kb/s |
| GFSK_LONG (25 kb/s) | 20/20 | 161 ms | 20/20 | 15.9 kb/s |
| MEDIUM_FAST (LoRa) | 20/20 | 987 ms | 20/20 | 2.2 kb/s |

As on the SX1280, ~30 kb/s is the PC side's ceiling (one message every ~50 ms from the Python library).

## Known limits

- Range not tested: all results come from one room.
- EU_868 allows a 10 % duty cycle; GFSK spends far less airtime per message, but the limit still applies.
